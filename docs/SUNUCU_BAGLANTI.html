Önce büyük resim

Tek bir kanal var ve iki yönlü çalışıyor. Bu dokümanda amber bizden gideni, teal sunucudan geleni gösterir.

BİZİM YKİ telemetrimiz · 1.8 Hz YARIŞMA SUNUCUSU
BİZİM YKİ hedef İHA konumu · aynı yanıtta YARIŞMA SUNUCUSU

En kritik nokta: hedefin konumu ayrı bir yerden gelmiyor. Biz telemetrimizi gönderiyoruz, sunucu aynı isteğe verdiği cevapta hedefin konumunu iliştiriyor. Yani sormadan öğrenemiyoruz — hedef verisinin tazeleme hızı, bizim gönderim hızımızdır.

Üç kapı, o kadar

Haberleşme dokümanında toplam üç adres tanımlı. Hepsi HTTP + JSON.

AdresNe işe yararNe zaman
POST /api/girisOturum açar. Kullanıcı adı ve şifre gider, sunucu bize bir çerez verir.Bir kez, en başta
GET /api/sunucusaatiSunucunun saatini söyler. Kilitlenme paketinde onun saati kullanılmalı, bizimki değil.Başta ve gerektikçe
POST /api/telemetri_gonderAsıl kanal. Dronumuzun durumunu gönderir, cevabında hedefin konumunu getirir.Saniyede 1.8 kez, sürekli

Sırayla ne oluyor

Program bunları kendisi yapıyor. Burada anlatılan, arka planda dönen şey — testte ne göreceğini bilmen için.

  1. Oturum açılır

    bizden gider 
    POST http://10.0.0.10:10001/api/giris
{
  "kadi": "hamidiye",
  "sifre": "Z8vN1cR5tY"
}

    Sunucu 200 döndürür ve bir çerez verir. O çerezi bundan sonraki her istekte taşıyoruz — kimliğimiz odur. 401 alırsak kullanıcı adı/şifre yanlıştır.

  2. Sunucu saati alınır

    sunucudan gelir 
    GET /api/sunucusaati
{ "saat": 11, "dakika": 38, "saniye": 38, "milisaniye": 739 }

    Kilitlenme bildirirken zamanı sunucunun saatiyle vermek zorundayız. Bizim bilgisayarın saati birkaç saniye kaymış olabilir; puanlama onunla değil bununla yapılıyor.

  3. Telemetri gönderilir — saniyede 1.8 kez

    bizden gider

    Dronumuzun o anki hâli. On dört alan; hepsi doküman §7.1'de tanımlı.

    POST /api/telemetri_gonder
{
  "takim_no": 2,
  "enlem": 41.5087750,   // dronumuz nerede
  "boylam": 36.1183350,
  "irtifa": 38.0,        // yerden metre
  "dikilme": 7.0,        // pitch, derece
  "yonelme": 210.0,      // yaw, 0-360
  "yatis": -30.0,        // roll, derece
  "hiz": 28.5,           // m/s
  "mod": 1,              // 0 manuel, 1 otonom
  "kilitlenme": 1,       // 0 yok, 1 var
  "hedef_x_merkezi": 300,   // kameradaki kutunun
  "hedef_y_merkezi": 230,   // merkezi ve boyutu,
  "hedef_genislik": 30,     // piksel
  "hedef_yukseklik": 43
}

    Dikkat

    mod alanı, panelde ne seçili olduğunu değil gerçekte otonom komut gidip gitmediğini söyler. Yapmadığımız bir şeyi beyan etmiyoruz — puanlama otonomluk üzerinden yapıldığı için bu önemli.

  4. Cevapta hedefin konumu gelir

    sunucudan gelir 
    {
  "sunucu_saati": { "saat": 11, "dakika": 38, ... },
  "hedef_iha_verileri": [
    {
      "takim_no": 1,
      "enlem": 41.5087750,
      "boylam": 36.1183350,
      "irtifa_ev": 38.0,
      "hiz": 28.5,
      "saat_farki": 85     // verinin yaşı, milisaniye
    }
  ]
}

    saat_farki bize verinin ne kadar eski olduğunu söyler. Program bunu yaşa ekliyor: 1.5 saniyeden eski bir konumu hedef yok sayıyor. Sebebi basit — 20 m/s giden bir uçak 1.5 saniyede 30 metre yol alır; eski bir konuma nişan almak, uçağın artık olmadığı yere nişan almaktır.

  5. Gelen konum temizlenir

    Hedefin GPS'i bize kasten bozulmuş geliyor: gürültü, ani sıçramalar, kesintiler, gecikme. Program bunu bir Kalman süzgecinden geçiriyor — uçağın nasıl hareket ettiğini modelleyip, fiziğe uymayan sıçramaları reddediyor ve gecikmeyi ileriye taşıyarak kapatıyor.

    Panelde gnss satırında görürsün: kaç ölçüm süzüldü, kaç tanesi reddedildi.

Hız kuralı — en kolay ceza yeme yolu

Doküman §7

“Takımlar en az 1 Hz ile göndermelidir. 2 Hz üzerinde gönderilen paketler 400 durum kodu ile 3 hata kodu ile cevaplanır.”

Yani hızlı göndermek bizi ödüllendirmiyor, cezalandırıyor. Ama yavaş göndermek de hedefi geç öğrenmek demek — çünkü hedef verisi cevapta geliyor.

1.8 Hz seçtik. Üst sınıra pay bırakıyor, hedefi olabildiğince taze alıyoruz. Program ayrıca ikinci bir fren koyuyor: yarım saniyeden sık göndermeyi kendi reddediyor, saat kayarsa diye.

HızPaketler arasıHedef 20 m/s giderken kat ettiği yol
1.0 Hz1.00 s20 metre
1.8 Hz0.55 s11 metre
2.0 Hz0.50 s10 metre — sınır, riskli

Aradaki bu 11 metreyi süzgecin “ölü hesap” ve “ileri taşıma” mekanizmaları kapatıyor.

Hakeme sorulacak tek şey

Doküman §8 “her başarılı kilitlenmeden sonra sunucuya kilitlenme bilgisi gönderilmelidir” diyor — ama §4'teki adres listesinde o adres yok. Kodumuz /api/kilitlenme_bilgisi varsayıyor. Yanlışsa paketler 404 alır ve kilitlenme puanı alamayız. Testte mutlaka sor.

Test masasında kontrol listesi

  • Ethernet kablosu takılı, ping 10.0.0.10 cevap veriyor
  • python3 araclar/sunucu_testi.py yeşil bitiyor
  • hata: 0 ve gönderim hızı 2.0'ın altında
  • Hedef verisi geliyor, yaş 1.5 saniyenin altında
  • Kilitlenme uç adresi hakemden teyit edildi
  • Takım numarası 2 olarak doğrulandı
